## Background

Large language models (LLMs) have demonstrated substantial capabilities in scientific writing, information retrieval and statistical reasoning. However, conventional LLM-based chatbots primarily generate text and cannot independently interact with datasets or execute statistical analyses. AI agents extend these capabilities by allowing an LLM to interact with external tools, such as code-execution environments, databases and software applications.

A recent example is Finch, a scientific data-analysis agent capable of autonomously writing and executing Python or R code within a Jupyter environment. Rather than following a predefined statistical script, the agent can inspect a dataset, execute analyses, observe the resulting outputs or errors, modify its code and continue iteratively until it reaches a final result.

This architecture may be particularly relevant to clinical registry research. Registry studies typically consist of a sequence of relatively structured tasks: defining the study cohort, identifying variables, evaluating missing data, calculating descriptive statistics, performing statistical analyses, generating tables and figures, checking model assumptions and interpreting the results.

Whether an AI agent can perform these tasks accurately, reproducibly and without introducing clinically or statistically important errors remains largely unknown.

Orthopaedic registries provide an attractive environment in which to evaluate such systems. They contain structured clinical variables and patient-reported outcome measures and are frequently analysed using established epidemiological and statistical methods.

The present study will therefore evaluate whether an AI data-analysis agent can autonomously perform predefined analyses of orthopaedic registry data and reproduce results generated by experienced human researchers.

## Overall aim

To evaluate the accuracy, reproducibility and safety of an AI agent performing statistical analyses of orthopaedic registry data.

## Primary research question

Can an AI data-analysis agent correctly and reproducibly execute predefined orthopaedic registry analyses when provided with a research question, data dictionary and dataset?

## Secondary research questions

The study will also investigate:

- whether agentic access to executable Python or R improves performance compared with an LLM without data-analysis tools;
- whether registry-specific instructions improve performance compared with a general-purpose data-analysis agent;
- which types of errors AI agents most frequently make;
- whether independently repeated agent analyses produce consistent results;
- how much human time is required to perform the same analyses;
- and whether AI-generated analyses can provide fully reproducible statistical code, tables and figures.

## Study design

The project will be conducted in two stages.

### Phase 1 – Synthetic registry data

A synthetic hallux valgus registry dataset will be generated containing approximately 500–1,000 simulated patients.

The dataset will resemble a typical orthopaedic quality registry and contain variables such as:

- age;
- sex;
- BMI;
- baseline hallux valgus severity;
- operative technique;
- concomitant Akin osteotomy;
- baseline SEFAS;
- one-year SEFAS;
- follow-up status.

The data-generating process will deliberately contain several known associations.

Because the dataset will be simulated, the underlying truth will be known.

This will allow evaluation of whether the agent correctly identifies both true associations and true null associations.

#### Example task

The agent may receive the following instruction:

> Determine which baseline patient and surgical factors are associated with improvement in SEFAS one year after hallux valgus surgery. Describe the cohort, assess missing data, perform appropriate adjusted analyses, assess model assumptions, and provide reproducible tables and figures.

The agent will receive:

research question + dataset + data dictionary

but will not receive a predefined statistical script.

The purpose of Phase 1 is primarily technical validation and development of the agent architecture.

### Phase 2 – Historical orthopaedic registry data

Following successful validation using synthetic data, the agent will be evaluated using historical pseudonymised orthopaedic registry data from analyses that have already been completed by human researchers.

A suitable initial dataset would be a hallux valgus registry cohort in which the study population, variables, statistical analyses and final results are already known.

This has an important methodological advantage: the AI analysis can be compared against a completed human analysis without allowing the AI output to influence the reference standard.

The original human analysis will therefore serve as the principal reference analysis.

Potential research questions may include:

- association between baseline hallux valgus severity and one-year SEFAS improvement;
- association between age and postoperative PROM improvement;
- comparison of operative techniques;
- association between additional Akin osteotomy and outcome;
- predictors of loss to follow-up.

The initial pilot could include approximately 10–20 separate analysis tasks of varying difficulty.

## AI systems

Three analysis conditions will be evaluated.

### 1. LLM without execution tools

The LLM will receive the research question and data dictionary and will be asked to describe how the analysis should be performed.

It will not be allowed to execute code or directly interrogate the dataset.

This represents conventional chatbot-based statistical assistance.

### 2. General-purpose data-analysis agent

The LLM will receive:

research question + data dictionary + dataset + Python/R execution environment

The agent will be able to inspect the dataset, write statistical code, execute it and respond iteratively to the resulting output.

The architecture will follow a Finch-like reasoning–action loop:

```
Inspect data
    ↓
Write code
    ↓
Execute code
    ↓
Observe output
    ↓
Reason about result
    ↓
Modify or continue analysis
    ↓
Repeat
```

All code and outputs will be stored in a Jupyter notebook to provide a complete audit trail.

### 3. Registry-specific AI agent

The third system will use the same underlying model and execution tools but will receive additional instructions specific to clinical registry research.

For example, the agent will be explicitly instructed to:

- define the study population before analysis;
- report absolute numbers and denominators;
- examine missing data;
- distinguish baseline from follow-up variables;
- avoid inappropriate complete-case exclusion without justification;
- report effect estimates with confidence intervals;
- assess relevant statistical assumptions;
- distinguish statistical from clinical significance;
- avoid post-hoc alteration of the primary research hypothesis;
- clearly label exploratory analyses;
- avoid claiming causality from observational associations.
